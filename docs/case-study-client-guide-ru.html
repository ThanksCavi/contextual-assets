Гайд по заполнению Case Study в Webflow CMS

Короткая инструкция для редактора: как создать новый кейс, заполнить нужные поля, собрать секции и блоки, проверить страницу и опубликовать все связанные элементы.

Актуальные примеры для ориентира: TFS Global, BDR, Milrose Consultants. Архивный пример Success Story не используйте как основной образец.

1. Что такое Case Study в админке

Case Study - это не один изолированный элемент, а набор связанных записей в CMS.

Основные коллекции

  • Case Studies - главная страница кейса: клиент, заголовок, hero, SEO, PDF, testimonial, homepage-поля.
  • Case Study Sections - разделы внутри страницы, например Challenge, Solution, Impact.
  • Case Study Blocks - контентные блоки внутри секций: цитаты, карточки, видео, изображения, timeline.
  • Categories - категория кейса.
  • Quick Facts - короткие факты о клиенте или проекте.

Связь между элементами

Сначала создается главный Case Study. Затем создаются секции, каждая секция привязывается к этому кейсу. Блоки тоже привязываются к тому же кейсу, а затем добавляются в нужные секции.

Простая схема: главный кейс → секции → блоки.

Не используйте для заполнения кейса: Client Logos и Lottie Image Sets. Для обычного создания Case Study они не нужны.

2. Порядок заполнения

  1. Создайте новый элемент в Case Studies.
  2. Выберите существующую Category или создайте новую.
  3. Выберите существующие Quick Facts или создайте новые короткие факты.
  4. Заполните основные поля главного кейса: hero, SEO/listing, Project at a Glance, homepage-поля, testimonial, PDF и переключатели видимости.
  5. Создайте элементы в Case Study Sections: Challenge, Solution, Impact и, если нужно, Story.
  6. Создайте элементы в Case Study Blocks для цитат, карточек, изображений, видео или дополнительных текстовых блоков.
  7. Откройте каждую секцию и добавьте в поле Blocks нужные блоки в правильном порядке.
  8. Проверьте Preview, убедитесь, что все выглядит корректно, затем опубликуйте новые или измененные связанные элементы.

3. Поля главного Case Study

Главный элемент управляет основными данными страницы, hero-блоком, карточками на сайте, PDF, testimonial и некоторыми секциями шаблона.

Группа Поля Как заполнять
Обязательные Name, Slug, Client Name, Title Name удобно делать по имени клиента. Slug должен быть коротким и понятным. Title - главный заголовок страницы.
Hero Client Logo, Featured Image, Category, Quick Facts Добавьте логотип, главное изображение, одну категорию и несколько коротких фактов. Эти поля помогают сразу понять, чей это кейс и о чем он.
SEO и listing Meta Description, Excerpt Meta Description используется для поискового описания. Excerpt - короткое описание для карточек и списков.
Project at a Glance Glance About, Glance AI Solution, Glance Results Заполните кратко: кто клиент, какое AI-решение было создано, какие результаты получены.
Homepage / featured Featured Project, Case Study Spotlight Order, Client Description, Supporting Image, Problem, Solution Delivered, Business Outcome Заполняйте, если кейс должен показываться в homepage spotlight. Если кейс не нужен на главной, обычно достаточно оставить Featured Project выключенным.
Testimonial Testimonial Image, Testimonial Quote, Testimonial Attribution Используйте для клиентской цитаты. Если изображения нет, цитата может отображаться без фото.
PDF и ссылки Case Study PDF, Project URL, Related Case Study Override PDF включает кнопку загрузки. Project URL нужен только если есть внешняя ссылка на проект или сайт клиента. Related override используйте только если нужно вручную выбрать связанный кейс.
Видимость Hide "The Compounding Advantage" Section, Hide "CTA" Section Включайте переключатель, если соответствующий блок на странице нужно скрыть.
Старые plain text поля Client Details, AI Solution Area и Delivery Timeline не используйте как основной источник данных. Для коротких фактов выбирайте Quick Facts.

4. Секции Case Study

Секция - это крупный раздел страницы. Она управляет заголовком, текстом, подписью в навигации и набором блоков внутри раздела.

Поле Что означает
Name, Slug Внутреннее название и адрес элемента. Удобный формат названия: "Client / 01 Challenge".
Case Study Главный кейс, к которому относится секция. Выбирайте тот же кейс, для которого создаете страницу.
Order Порядок секций на странице. Используйте 1, 2, 3 и так далее.
Nav Label Короткая подпись для боковой навигации. Например: Story, Challenge, Solution, Impact.
Heading Основной заголовок секции на странице.
Body Основной текст секции. Поле можно оставить пустым, если секция состоит только из блоков.
Blocks Список блоков, которые появятся внутри секции. Порядок в этом поле важен.

Рекомендуемая структура

  • Challenge - проблема или ограничение до внедрения решения.
  • Solution - что было создано и как это работает.
  • Impact - результаты, метрики и бизнес-эффект.

Если кейсу нужен сильный вводный рассказ или цитата перед Challenge, добавьте секцию Story перед основными секциями. Такой подход можно использовать по примеру Milrose Consultants.

5. Блоки Case Study

Блок - это отдельный контентный элемент внутри секции. Каждый блок должен быть привязан к правильному Case Study и добавлен в поле Blocks нужной секции.

Главное правило: выберите один Block Type и заполняйте только поля, которые относятся к этому типу. Не смешивайте цитату, карточки, видео и изображение в одном блоке.
Block Type Какие поля заполнять Когда использовать
Rich Text Rich Text Block Для дополнительного текста, списков, простых подзаголовков.
Image Image Block Для отдельного изображения или скриншота внутри секции.
Video Video Block Для видео-демо или другого встроенного видео.
Quote Light, Quote Dark Quote Label, Quote Text, Quote Name, Quote Details Для короткой цитаты. Light и Dark отличаются визуальным стилем.
Stat Cards, Stat Cards Small Card 1-4 - Heading и Card 1-4 - Text Для набора фактов, показателей или "before AI" карточек.
Metric Cards Card 1-4 - Heading и Card 1-4 - Text Для итоговых метрик и результатов в секции Impact.
Checklist Cards Card 1-4 - Heading и Card 1-4 - Text Для шагов решения, возможностей продукта или списка действий.
Timeline Rich Text Block при необходимости, затем Card 1-4 - Heading и Card 1-4 - Text Для временной шкалы: недели, этапы проекта, запуск и дальнейшее развитие.

6. Опциональные поля и скрытие

В CMS много полей необязательные. Простое правило: если поле не заполнено, связанный элемент на странице обычно не показывается или остается пустым. После заполнения всегда проверяйте Preview.

Особенно важно проверить

  • Case Study PDF: если PDF не добавлен, кнопка загрузки может быть не нужна.
  • Testimonial Quote и Testimonial Attribution: без текста testimonial лучше не использовать.
  • Project URL: оставляйте пустым, если нет внешней ссылки.
  • Homepage-поля: заполняйте только для featured-кейсов.
  • Body в секции: можно оставить пустым, если весь контент идет через blocks.

Переключатели

  • Hide "The Compounding Advantage" Section: скрывает соответствующий большой блок страницы.
  • Hide "CTA" Section: скрывает нижний CTA-блок.
  • Featured Project: включает показ кейса в homepage spotlight, если остальные homepage-поля заполнены.

7. Что есть в шаблоне страницы

Шаблон Case Study в Designer доступен для проверки. В нем предусмотрены hero, quick facts, блок Project at a Glance, кнопка загрузки PDF, боковая навигация по sections, контентные blocks внутри sections, testimonial, related stories, CTA и блок "The Compounding Advantage".

Для редактора это означает: не все поля нужны в каждом кейсе. Заполняйте только те элементы, которые действительно должны появиться на странице, а затем проверяйте результат в Preview.

8. Чеклист перед публикацией

  • Главный Case Study создан, обязательные поля заполнены.
  • Category выбрана или создана и опубликована.
  • Quick Facts выбраны или созданы и опубликованы.
  • Все sections привязаны к правильному case.
  • Все blocks привязаны к правильному case.
  • Blocks добавлены в нужные sections через поле Blocks.
  • Order у sections выставлен правильно: 1, 2, 3 и далее.
  • Изображения добавлены там, где они нужны: logo, featured image, supporting image, testimonial image или image blocks.
  • SEO заполнено: Meta Description и короткий Excerpt.
  • PDF, testimonial, project URL и homepage-поля заполнены только там, где они действительно нужны.
  • Preview проверен: hero, quick facts, секции, блоки, PDF-кнопка, testimonial, CTA и related stories выглядят корректно.
  • Опубликованы все связанные items: Category, Quick Facts, Blocks, Sections и сам Case Study.
Документ предназначен для редакторов Webflow CMS. Названия полей оставлены на английском, чтобы их было легко найти в админке.
